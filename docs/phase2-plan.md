## 1. 完成判据（做完什么样算过）

1. 从 `*start` 起跑，agent 只靠 MCP 工具就能：警告页 → 标题菜单点「Start」→ 进序章 → 连续推进到第一章结束

## 2. 关键机制（先摸清，再动手）

### 2.1 `csel` 不是引擎内置的选择框

Jh 的 `selectCommand` 在 `SELECT_CSEL_MODE` 下只做三件事：
解析 `(文本, 标签)` 对 → `saveoff` → `setCurrentLabel("customsel")` 直接跳过去
（`ONScripter_command.cpp:879`）。所以真正的选择界面写在脚本里：

```
8808  csel "射在里面",*L_w_08_04_sel1_0,"射在外面",*L_w_08_04_sel1_1
       └─ 引擎把两对 (文本,标签) 存进 select_link，然后跳到 *customsel

25918 *customsel
25927   getcselnum %selectnum          ; 选项个数
25928   getcselstr $select00,0         ; 第 0 项文本
25935   if %selectnum>=1 lsp 553,":s/24,24,2;#FFFFFF"+$select00,535,225
25936   lsp 554,"cgsys/sys/selectbutton_off.png",350,205
25937   lsph 555,"cgsys/sys/selectbutton_on.png",350,205
25938   exbtn 554,554,"C554P555S1,(...)"     ; 悬停换图
25956   btnwait %bwait
25957   if %bwait=554 ... cselgoto 0         ; 选中项 → 跳回对应标签
```

结论：二阶段要实现的不是"画一个选项框"，而是这条链路
**`csel` 解析 → 跳 `*customsel` → `getcselnum/getcselstr` → `btnwait` 命中 → `cselgoto`**。

### 2.2 三种按钮，命中区都是矩形

| 命令 | 命中区 | 用途 |
|---|---|---|
| `spbtn sprite,no` | 该精灵的图片矩形 | 把已有精灵当按钮（标题页"跳过"） |
| `exbtn sprite,no,"ctl"` | 该精灵的图片矩形 | 复合按钮：ctl 控制悬停/按下时哪些精灵显隐 |
| `btn no,x,y,w,h,...` | 显式给的矩形 | 老式矩形按钮，配 `btndef` 图片 |

`exbtn` 的 ctl 串语义（`decodeExbtnControl`）：
`C<n>`/`C<n>-<m>` 隐藏（区间）、`P<n>[,cell]` 显示、`S<n>,(wav)` 放音、`M<n>,x,y` 移动。
`exbtn_d` 是所有 exbtn 的空闲态 ctl（本作是 `P554C555...`，即"显示底图、隐藏悬停图"）。

注意：`exbtn`/`spbtn` 在精灵没有图片时会**静默不注册**（引擎源码里直接 return），
所以第一阶段的 `lsp` 必须先把图真的加载进来 —— 这一点已经满足。

### 2.3 `btnwait` 的返回值语义

正数 = 按钮 id；`0` = 空点；`-1` = 右键；`-10`/`-11` = ESC/空格；`-2`/`-12`/`-40` = 滚轮/历史。
agent 传坐标来点，我们做命中测试后把 id 写进 `%bwait`，然后继续执行。
后注册的按钮优先（引擎是头插，后来的盖住先来的）。

本作 21 处 `btnwait`：1 处警告页、1 处标题、1 处选择肢、其余在菜单/存读档/回想界面。

### T7/T8 结果（2026-10-23）

参照 = OnscripterYuri web 构建（`build_web`，没重新编译），同一份脚本、同一个 `default.ttf`、
同一组 `setwindow3 300,600,32,3,26,26,0,10,1,1,1,...`，无头 Edge 截图后与我们逐项比：

| 项 | 参照 | 我们 | 差 |
|---|---|---|---|
| 行数 | 3 | 3 | 0 |
| 首行上沿 y | 601.0 | 601.0 | 0.0 |
| 行距 | 36.5 | 36.5 | 0.0 |
| 字高 | 25.3 | 25.3 | 0.0 |
| 左边距 x0 | 301.0 | 301.0 | 0.0 |
| 右端 x1 | 1130.0 | 1130.0 | 0.0 |

像素差异：平均 1.49/255，明显差异 0.50%；把参照经历过的浏览器缩放也加到我们这边之后，
明显差异降到 **0.08%**（只剩字形抗锯齿边缘）——排版与引擎一致，不需要调参。

踩到的两个坑（都记进 `tools/` 注释了）：
1. 参照脚本第一行必须是 `;$S1280,720G1500`，否则引擎按 640x480 跑，`y=600` 的文本框跑到画面外；
2. 文本行末尾要有 `\`（clickwait），否则引擎打完字直接跑到脚本末尾（日志 `***** End *****`、全黑）。

## 4. 已知风险

| 风险 | 影响 | 处理 | 现状 |
|---|---|---|---|
| 悬停态不实现 | agent 看不到按钮高亮，但能点 | 按空闲态（`exbtn_d`）渲染，命中测试用同一套矩形 | 仍未实现（agent 用 `buttons()` 拿矩形自己点，不需要 hover 视觉） |
| 存读档界面用了 `bar`/`cell`/`msp`/九宫格 | 界面显示不全 | 不影响流程（agent 用 MCP 自带 `save`/`load`），二次修 | 仍是已知差距（`bar` 画成实色块、`cell` 只显示第 0 格） |
| `%click`/`%sceneon` 等 UI 门控变量初值不对 | 走进不同分支（比如 exbtn 不注册） | T4 里逐段核对变量 | 已解决（数字变量名 `%1`/`$0` 的分词 bug 是根因） |
| 文本排版仍未与引擎逐像素对齐 | 视觉差异 | 与流程无关，可延后 | 已解决（几何项全 0 偏差，像素差 0.08%） |

## 5. 已确认（2026-10-23）

| # | 决策 | 结论 |

| 1 | 操作接口 | `choices()` 返回 `{index, text, button_id, rect}`；`click(x,y)` 点坐标；**另加 `choose(index)`**，可选再加 `buttons()` 调试 |
