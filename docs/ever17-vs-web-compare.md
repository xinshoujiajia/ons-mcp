# Ever17 逐句比对记录（ons-mcp vs 原版浏览器）

比对方法：原版用 OnscripterYuri 的 web 构建（`build_web`）在无头 Edge 里跑同一份
`ever17_packed/Ever17`；我们用 MCP 的 ons-mcp（0.19.0）跑同一目录。
两边从标题画面开始，每次各点一下，各截一帧，做像素比对。
比对工具：`tools/webdrive/drive.js`（CDP 驱动原版）+ `tools/webdrive/ours_shot.py`
（我们自己的引擎落盘）+ `tools/webdrive/cmp.py`（像素 diff）。

结论先行：**台词文字内容、文本框位置与外观完全一致**；差异集中在
「每行是否停」、「背景特效时机」、「片头动画」、「章节日期转场」四处。

## 差异 1：原版菜单是一片黑框（原版自身缺陷，非我方问题）

原版 web 构建在标题画面把菜单区画成**纯黑矩形**（该区域 100% 为 (0,0,0)，
五个菜单项一个都看不到），但点击仍然有效——点 (405,327) 能正常进游戏。
我们这边五个菜单项（New Game / Continue / Option / Special / Exit）都正常显示。

即：这一条是**原版浏览器构建的渲染缺陷**，不是我们的偏差，不需要改。

## 差异 2：片头动画

原版点 New Game 后会先播一段约 136 秒的片头 MP4（`<video>` 元素接管，canvas 被隐藏），
播完才回到标题，再点一次才进正文。
我们直接跳过动画进入正文（`mpegplay` 是设计上的桩）。

影响：进度节奏不同，但文字内容没错。属已知取舍。

## 差异 3：每句台词是否单独停 —— ✅ 已修复（0.20.0）

**修复后实测**：第 1~22 句的显示内容与原版**逐句一致**（含折行位置），
每帧一行/两行的节奏全对：

```
0: 他，站在蓝色世界的正中央。
1~6: 触目所及 / 五月的太阳 / 抬头仰望 / 初生的天空（折 2 行）/ 四周的景色 / 延伸至远方的地平线
7: 【武】 / “真是悠闲啊……”          ← 名字行+台词同屏
8~12: 他喃喃地道 / 一只海鸥 / 带着海洋味道的微风 / 身后是喧闹的人群 / 孩子们的…（折 2 行）
13: 【武】 / “真是个和平的世界呀……”  ← 同上
14: 仿佛置身于梦境之中。
15: [delay] 章节日期画面              ← 差异 5 修好后出现
16~21: 东京都… / 漂浮…（2 行）/ 看着…（2 行）/ 事实上…（2 行）/ ‘天国在何方？’ / ‘就在那片天空中…’
```

**根因**：不是引擎的 `clickstr_line` 机制，是我们没解析台词标签的第 2 段。
Ever17 的标签是 `[voice|needClear]`：

* `|1` → 这句起新页（上一句消失）
* `|0` → 续在前一页（名字行 + 台词行因此同屏）

脚本自己在 `*procPreGo` 里 `split $0,"|",$voice,$needClear`，被注释掉的两行
`if $needClear==1 textclear` / `==0 locate %lastPosition+1,0` 就是原作者的意图。

**修法**：`_split_tag` 拆出 `need_clear` 并交给起页判断；`voice` 同时拆干净
（否则脚本 `split` 会拿到 `NONE|0` 这种带尾巴的值）。万华镜没有这种标签，
照旧走 `linepage`，行为不变。

原版：每点一次只显示**当前这一句**，上一句消失。
我们（0.19.x）：多句累积在同一页里，一次显示 2~3 句。

| 第 13 句 | 【武】／"真是个和平的世界呀……" | 【武】／"真是个和平的世界呀……"（2 行，一致） |

规律：**名字行（【武】）＋台词是同一个文本单元**，两边都会一起显示，一致；
差异全在纯叙述句——原版逐句换，我们逐句累积到页满（4 行）才换。

连带效应（第 17 句起观察到）：累积会让两边**帧内容错位**——我们每帧比原版多
推进一句，于是原版第 N 句的内容出现在我们第 N-1 帧里，场景切换也跟着提前
（如原版第 20 句还在岛屿全景时，我们第 20 帧已经切到石碑特写）。
折行位置本身两边一致（"…远方摇｜晃着。"、"…探出头｜来，…"折点相同）。

Ever17 的脚本写法是每条台词各占一行、行尾都带 `\`（L723~L729 连续七条），
`setwindow3 50,435,25,4,...` 设定 4 行文本框。
这不是 Ever17 独有——万华镜的台词行同样以 `\` 结尾，所以是**共性问题**，
只是之前没有逐句比对过，所以没暴露。

## 差异 4：背景特效的时机

第二句起原版背景仍是**纯黑**，我们已经是海景终态（蓝天/海鸥/甲板）。
原版从第 2 句一直到第 15 句背景**始终是黑的**，点击无法推进它。

脚本在 L701 用 `specialEffectImage "00000000","BG41A1",6,2,12,12,775,581`
按格揭开背景。原版在 web 构建里这个特效始终没有完成（点了十几次仍是黑），
我们直接给终态。
这是quirks 里已记录的取舍（特效不做，直接出终态），不是新问题。

同一现象在第 26~34 句重现：狸的特写 CG（事件图，含第 33 句起粉色头发女孩入镜）
在原版同样是**纯黑**，我们正常显示 CG。文本内容（含【？？】名字行）两边一致。

**第 37 句修正**：原版的 CG 不是永远不出——连续点击约 11 次后（第 37 句）
终于显示了，且显示出来的 CG 与我们**完全一致**（狸、少女、尾巴上的白貂、
黄色感叹号气泡都相同）。即原版 web 构建的特效是"极慢速/按点击逐格揭开"，
中间有十几次点击的黑屏窗口期；我们直接出终态。

## 差异 5：章节日期转场画面缺失 —— ✅ 已修复（0.20.0）

**修复后实测**：第 16 句（日期画面）与原版差异 **0.01%（40 像素）**，
「5月1日 月曜日」+「Der erste Tag」+ 蓝色环形结构全部一致。

**根因**：不是缺命令 —— `chapterCutin` 是脚本 `defsub` 的宏（L39 defsub chaptercutin），
展开后是 `textoff : bg "background\cal_501.jpg",10,1000 : delay 1000`，
而 `defsub`、`bg` 我们都实现了，`cal_501.jpg` 也在 `arc.nsa` 里（本身就是整张日期图）。
问题在最后一环：**`bg` 的渐变参数没读、`delay` 是 no-op**，于是
`bg cal_501` → `bgload BG38A2`（L752）在同一次 run 里连续执行，
日期画面存在过一瞬间但**一帧都没被合成**。

**修法（方案 B）**：`delay >= 800ms` 退化成"留一帧的暂停"（`waiting="delay"`），
画面先合成等人看，下一次 click 继续。阈值 800 是拿 Ever17 实际分布定的：

* 章节画面 `delay 1000` → 留帧 ✅
* 时钟数字逐位动画 `delay 500`×3、标题转场 `delay 700` → 跳过（不然每次多点 4 下）

另修一处：`textoff` 之前只关文字、不关窗口框，日期画面上会残留一个绿框；
现在 `textoff` 关整个文本层（只藏文字的是 `texthide`）。

### 修复前的观察（留档）

第 16 句两边**完全是两个画面**：原版显示日期章节画面（全屏、无文本框、停住等点击），
我们直接跳到下一场景（岛屿鸟瞰图 + 「东京都驹原诸岛M岛海面１６公里。」）。

## 差异 6：原版有逐字显示（我们一次给全）

用「点击后分别等 0 / 0.5 / 2 秒截三帧」的实验证实（第 25 句，台词"‘那就是乐园……吗？’"）：

| 等待 | 原版显示 |
|---|---|
| 0 秒 | 【武】／"那就是乐（仅 5 字） |
| 0.5 秒 | 【武】／"那就是乐园……吗？"（完整） |
| 2 秒 | 同上，稳定 |

即原版按约 10 字/秒逐字打出。我们一次给全。
影响：截图时机早于 0.5 秒时会读到半句；内容本身无差异，不是缺陷。
（此前第 23 句出现的"半句"即此现象，非内容缺失。）

连带节奏（第 48 句观察到）：逐字进行中时**第一击被动画吸收**（仅用于立即
显示完整文本），第二击才真正推进到下一句。所以驱动原版时偶尔会遇到
"点了没反应"，需要再点一次——这不是脚本卡住。
